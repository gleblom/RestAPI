## ⚡ Быстрый старт

### Вопрос: Как работает система согласования документов?

**Ответ за 30 секунд:**

```
Документ проходит через маршрут согласования:

1️⃣  Автор создает документ (DRAFT)
2️⃣  Загружает файл
3️⃣  Отправляет на согласование (IN_PROGRESS)
4️⃣  Согласующие одобряют один за другим
5️⃣  Последний согласующий опубликовал (PUBLISHED)

Если отклонено → Автор загружает новую версию → Повторное согласование
```

**Полный процесс:** [ADVANCED_DOCUMENTATION.md — Сценарий 1](ADVANCED_DOCUMENTATION.md#сценарий-1-простое-линейное-согласование)

## 🎯 Главные компоненты

### ⭐ Модуль согласования (approval_service.py)

**Три критические функции:**

1. **`submit_document_service()`** — Отправить на согласование
   - Проверяет права автора
   - Находит первого согласующего
   - Создает запись согласования
   - **Сложность:** ⭐⭐⭐⭐⭐

2. **`approve_document_service()`** — Согласовать документ
   - Одобряет текущий этап
   - Переходит на следующий или публикует
   - **Сложность:** ⭐⭐⭐⭐⭐

3. **`reject_document_service()`** — Отклонить документ
   - Требует комментарий отклонения
   - Возвращает документ автору
   - **Сложность:** ⭐⭐⭐⭐

[Подробные описания →](DOCUMENTATION.md#ключевой-модуль-согласование-документов)

## 📋 API endpoints

### Согласование
```
POST /documents/{id}/submit           # Отправить на согласование
POST /documents/{id}/approve          # Согласовать
POST /documents/{id}/reject           # Отклонить
```

### Документы
```
POST /documents/create                # Создать
GET  /documents/{id}                  # Получить
GET  /documents                       # Список с фильтрацией
POST /documents/{id}/versions         # Загрузить версию
```

### Маршруты
```
POST /routes                          # Создать маршрут
POST /routes/{id}/nodes               # Добавить этап
POST /routes/{id}/edges               # Добавить связь
GET  /routes/{id}/graph               # Граф для визуализации
```

## 🔐 Безопасность

### Контроль доступа

- **По компаниям:** Каждая компания видит только свои данные
- **По ролям:** Директор, администратор, делопроизводитель, сотрудник
- **По документам:**
  - Автор → видит всё
  - Опубликованный → видят все
  - Черновик → видит только автор

### Проверки

- JWT токены (access + refresh)
- Двухфакторная аутентификация (TOTP)
- Rate limiting на попытки входа (5 попыток = блокировка на 1 минуту)

## 📈 Жизненный цикл документа

### Статусы

| Статус | ID | Описание |
|--------|----|---------
| DRAFT | 2 | Черновик (видит только автор) |
| IN_PROGRESS | 3 | На согласовании |
| PUBLISHED | 1 | Опубликован (видят все) |
| RETURNED | 4 | На доработке (после отклонения) |

### Цикл

```
DRAFT 
  ↓ (отправка на согласование)
IN_PROGRESS 
  ├─ (одобрение последовательно) → PUBLISHED ✅
  └─ (отклонение) → RETURNED 
       ↓ (загрузка новой версии)
       DRAFT (повторный цикл)
```
