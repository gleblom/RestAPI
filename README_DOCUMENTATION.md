## ⚡ Быстрый старт

### Вопрос: Как документ проходит согласование?

**Ответ:** За 6 шагов

```
1️⃣  Автор создает документ                   (DRAFT)
2️⃣  Автор загружает файл                     (DRAFT + версия)
3️⃣  Автор отправляет на согласование        (IN_PROGRESS, step=0)
4️⃣  Согласующий одобряет                    (IN_PROGRESS, step=1)
5️⃣  Следующий согласующий одобряет         (IN_PROGRESS, step=2)
6️⃣  Последний согласующий одобряет         (PUBLISHED) ✅
```

**Полный процесс:** [ADVANCED_DOCUMENTATION.md#сценарий-1-простое-линейное-согласование](ADVANCED_DOCUMENTATION.md#сценарий-1-простое-линейное-согласование)

## 🎯 Ключевые компоненты

### ⭐ Модуль согласования (САМЫЙ СЛОЖНЫЙ)

Содержит три критических функции:

#### 1. `submit_document_service()` — Отправить на согласование
- Проверяет права (только автор)
- Находит первый узел маршрута
- Создает запись согласования
- Отправляет уведомление согласующему

**Сложность:** ⭐⭐⭐⭐⭐ | [Подробно →](DOCUMENTATION.md#-сложная-логика-submit_document_service)

#### 2. `approve_document_service()` — Согласовать документ
- Проверяет текущего согласующего
- Отмечает этап как согласованный
- Переходит на следующий этап или публикует
- Отправляет уведомления

**Сложность:** ⭐⭐⭐⭐⭐ | [Подробно →](DOCUMENTATION.md#-сложная-логика-approve_document_service)

#### 3. `reject_document_service()` — Отклонить документ
- Требует комментарий отклонения
- Возвращает документ в статус RETURNED
- Отправляет причину автору
- Позволяет автору загрузить новую версию

**Сложность:** ⭐⭐⭐⭐ | [Подробно →](DOCUMENTATION.md#-сложная-логика-reject_document_service)

## 🔐 Безопасность и изоляция

### По компаниям
Каждая компания видит только свои данные (company_id в каждой таблице)

### По ролям
- **Директор** — управление компанией
- **Администратор** — управление пользователями и справочниками
- **Делопроизводитель** — создание маршрутов согласования
- **Сотрудник** — работа с документами

### По правам доступа к документам
- **Автор** → видит всё (черновики, историю)
- **Опубликованный** → видят все в компании
- **Опубликованный в отделе** → видят в отделе
- **Черновик коллеги** → 403 Forbidden

## 📊 Система маршрутов

### Граф структура
Маршруты представляют **Directed Acyclic Graph (DAG)**:

```
┌─────────────────────────────────────────┐
│ Маршрут: "Согласование финансов"        │
├─────────────────────────────────────────┤
│                                         │
│  Начальник отдела (step=0)              │
│         ↓                               │
│  Главный финансист (step=1)             │
│         ↓                               │
│  Директор (step=2)                      │
│                                         │
└─────────────────────────────────────────┘
```

### Ограничения
- ✅ **Поддерживается:** Линейные маршруты
- ❌ **НЕ поддерживается:** Параллельные ветви (циклы, несколько потомков)

## 📋 Статусы документа

| Статус | ID | Описание | Примечание |
|--------|----|---------|---------  |
| DRAFT | 2 | Черновик | Видит только автор |
| IN_PROGRESS | 3 | На согласовании | Документ в маршруте |
| PUBLISHED | 1 | Опубликован | Финальный статус |
| RETURNED | 4 | На доработке | После отклонения |

---

## 🔄 Жизненный цикл версии

Документ может иметь несколько версий:

```
Версия 1: На согласовании
  ├─ Шаг 0: Alice одобрила ✅
  ├─ Шаг 1: Bob ОТКЛОНИЛ ❌ (комментарий: "Требуются правки")
  └─ Документ: RETURNED

Автор загружает Версию 2
  └─ Документ: DRAFT (сброс для повторного согласования)

Версия 2: На согласовании
  ├─ Шаг 0: Alice одобрила ✅
  ├─ Шаг 1: Bob одобрил ✅
  ├─ Шаг 2: Charlie одобрил ✅
  └─ Документ: PUBLISHED ✅
```

## 📞 Часто задаваемые вопросы

**Q: Почему не поддерживаются параллельные согласования?**
A: Текущая модель DocumentApproval привязана к одному approver_id на step_index. Для параллельных нужна переработка модели данных. [Подробно →](ADVANCED_DOCUMENTATION.md#сценарий-3-параллельное-согласование-не-поддерживается)

**Q: Что происходит при загрузке новой версии?**
A: Документ возвращается в DRAFT, старая версия остается в истории. [Подробно →](DOCUMENTATION.md#create_document_version_service)

**Q: Как работает контроль доступа?**
A: По компаниям (company_id), ролям и статусам документа. [Подробно →](DOCUMENTATION.md#get_document_service)

**Q: Как отследить документ через систему?**
A: SQL запросы в [ADVANCED_DOCUMENTATION.md#трассировка-документа](ADVANCED_DOCUMENTATION.md#трассировка-документа-через-систему)

## 📈 Метрики для отслеживания

```sql
-- Среднее время согласования
SELECT AVG(EXTRACT(EPOCH FROM (updated_at - created_at))) / 3600 as hours
FROM documents WHERE status_id = 1;

-- Процент отклонений
SELECT COUNT(*) FILTER (WHERE is_approved = false) * 100.0 / COUNT(*)
FROM document_approvals;

-- Количество версий до публикации
SELECT AVG(version_count) FROM (
    SELECT COUNT(*) as version_count FROM document_versions 
    GROUP BY document_id
) t;
```
